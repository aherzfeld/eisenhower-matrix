# Eisenhower Matrix — build plan (v1, revised after red team)

## Goal and criteria
A single-user, browser-only web app for sorting tasks into the Eisenhower Matrix:

| | Urgent | Not urgent |
| --- | --- | --- |
| **Important** | **1 · Do** | **2 · Schedule** |
| **Not important** | **3 · Delegate** | **4 · Delete** |

Criteria the plan is judged against:
1. Capture-and-classify takes seconds, is keyboard-only capable, and forces an honest urgent/important call.
2. No silent data loss — storage failure, eviction, corrupt data, schema change, a second tab, bad import.
3. Every task is delegable as written: model tier, tests first, machine-checkable acceptance.
4. Simple: v1 is roughly a day of build time, with an explicit cut list and cut order.
5. **As useful as possible within that simplicity** (Andrew's preferred outcome): every v1 feature helps the user *act* on a sorted task. Features that only add weight are cut.

## Assumptions
- Single user, no accounts, no server. Data lives in `localStorage`, one key: `eisenhower:v1`.
- Static site. **Vite + TypeScript, no UI framework**; **Vitest + jsdom** for unit/component tests; **Playwright (Chromium)** for a small real-browser smoke suite; ESLint; GitHub Actions CI on Node 24 running typecheck, lint, unit tests (twice, under `TZ=America/Los_Angeles` and `TZ=Pacific/Auckland`), build, Playwright.
- Repo `aherzfeld/eisenhower-matrix` at `~/projects/eisenhower-matrix`.
- Hosting: public Cloudflare Pages, static only. Deploying is a separate ask.

## Architecture (ports and adapters)
```
src/
  core/                  pure — no DOM, no storage, no clock (time passed in)
    task.ts              Task type; create, rename, setFlags, setWhen, setWho, toggleDone, reorder
    validate.ts          the ONLY validators; used by task.ts ops AND codec.parse
    quadrant.ts          quadrantOf, flagsFor, QUADRANTS (1 Do, 2 Schedule, 3 Delegate, 4 Delete)
    dates.ts             localToday(now) → 'YYYY-MM-DD'; isDue(task, today)
    undo.ts              removal records; restore re-inserts by id
    codec.ts             serialize / parse → Result; version, validation, migrations
    ports.ts             Storage interface (load/save/subscribe) — defined in T1 so UI can build against a fake
  io/
    storage.ts           localStorage implementation of the Storage port
    download.ts          file download helper
  ui/
    render.ts            state → DOM; roving tabindex
    capture.ts           triage prompt (modal state)
    keys.ts              keyboard map with input guard
    banner.ts            persistent warnings
    transfer.ts          export / import controls and confirm panel
  main.ts                wiring
e2e/smoke.spec.ts        Playwright
```

### Data model
```ts
type Task = {
  id: string;            // crypto.randomUUID()
  title: string;         // trimmed; 1..200 chars after trim
  urgent: boolean;
  important: boolean;
  done: boolean;
  when?: string;         // LOCAL calendar date 'YYYY-MM-DD' (never a Date / UTC ISO)
  who?: string;          // trimmed 1..80; empty input → field removed
  order: number;         // position within its quadrant, contiguous from 0
  createdAt: string;     // ISO timestamp
  updatedAt: string;
};
type StoredState = { version: 1; rev: number; lastExportAt?: string; tasks: Task[] };
```
The quadrant is **derived** from `(urgent, important)` and never stored. Moving a task sets its flags and appends it to the destination's order.

**One set of validators** (`core/validate.ts`) guards both the edit operations and `codec.parse`. Property test: any state reachable through core ops serializes and parses back identically — the app can never write data it would later reject.

## Interaction design
**Keyboard map.** Global shortcuts are **ignored when focus is in an input, textarea or contenteditable, or `event.isComposing`** is set.

| Key | Action |
| --- | --- |
| `/` | Focus the capture input |
| `1`–`4` | Move the focused task to Do / Schedule / Delegate / Delete |
| `↑` `↓` | Move focus between tasks in a quadrant (roving tabindex: one Tab stop per quadrant) |
| `Alt+↑/↓` | Reorder within the quadrant |
| `Space` | Toggle done |
| `Enter` | Rename (inline) |
| `Delete` / `Backspace` | Remove (undoable) |
| `r` | Start review mode |

**Capture (triage).** Type a title in the capture input and press Enter. The app enters a **modal prompt**: "Important? Y/N", then "Urgent? Y/N". At the prompt only `y`/`Y`/`n`/`N`/`Esc` do anything; every other key is ignored, so there is no default answer. The task lands in its quadrant, and focus returns to the input. Importance is asked first so the call is anchored on value, not on the reflex "yes" to urgency.
KLM estimate beyond the title: K + M + K + M + K ≈ 3.5 s, no mouse.

**Quadrant follow-through (usefulness):**
- **Do:** the top open task is marked **Next**. Done tasks sink to the bottom and never take Next.
- **Schedule:** each row has an optional native `<input type="date">` (`when`). When `when ≤ today`, the row shows **Due** and a "Move to Do" button. Pressing `1` on it does the same, so no extra key is needed. Due status is recomputed on render, on `visibilitychange`, and on a timer at local midnight.
- **Delegate:** each row has an optional "Who?" text input. When set, the row shows **Waiting on <who>**.
- **Delete:** a **Drop all** button, undoable.

**Review mode** (`r`): walks through every open task in quadrant order and re-asks both triage questions, applying each answer immediately. `Esc` stops, keeping the answers given so far. With no open tasks, it shows "Nothing to review".

**Removal and undo.** Delete, Clear done and Drop all are saved immediately and show a toast with **Undo** for 5 s. Undo **re-inserts the removed tasks by id**; it does not restore a snapshot, so anything added during the window survives. A second removal replaces the toast, and its undo covers only that removal. Reloading during the window forfeits undo.

**Layout.** 2×2 grid at ≥ 640 px. Below that, quadrants stack in the order Do, Schedule, Delegate, Delete. No horizontal scroll at 375 px.

## Data safety
| Situation | Behaviour |
| --- | --- |
| `localStorage` throws on read or write | Memory mode. A persistent banner reads "Not saving: your browser is blocking storage. Export before closing." Any `setItem` throw counts as a failed save, whatever `error.name` says. |
| Save fails mid-session (quota) | Switch to memory mode. The banner stays until a later save succeeds. |
| Stored value fails `parse` | Write the raw value to `eisenhower:backup:<ts>` and **never overwrite the main key while the backup is missing**. If the backup write succeeds: start empty; the banner offers a download of the raw data. If the backup write fails: memory mode, main key untouched, banner offers the raw download. |
| Stored `version` is newer than the build | **Read-only memory mode, never writes.** Banner: "Saved by a newer version. Reload the page." |
| Migration needed | Write the original to `eisenhower:backup:pre-v<N>:<ts>` first. If that write fails, run in memory mode without saving. |
| Another tab changed the data | Listen for `storage` events and reload state from storage on each one. Backstop: every save re-reads the stored `rev`. If it differs from the rev this tab loaded, don't write; reload instead, with the banner "Changed in another tab. Your last change wasn't saved." |
| Browser evicts storage (Safari 7-day rule, private window) | Call `navigator.storage.persist()` at startup. Record `lastExportAt` and show "Last backup N days ago" in the footer, as a warning once it is over 7 days or never. |
| Import | Validate with `codec.parse` and show the task count. On confirm: (1) write the current state to `eisenhower:backup:pre-import:<ts>`; **if that write fails, abort** (when storage is full the panel says so: "Browser storage is full, so your current tasks couldn't be backed up and nothing was imported. Export your tasks, then clear some space."); (2) trigger an export download as a bonus; (3) replace. Cancel leaves state untouched. **Retention:** only after the new backup has read back identical, the storage adapter keeps the newest 3 pre-import backups (the new one always among them, the rest ordered by parsed timestamp, then `-N` suffix; a backup stamped later than the current time was written while the clock ran ahead, so it orders below every present-day backup and is removed first, #18; the clock changes which backups are removed, never how many, so a clock set behind can remove the newest ones instead) and removes older ones. It removes only keys that parse exactly as `eisenhower:backup:pre-import:<ISO ts>[-N]`, never the main key, corrupt-data or pre-migration backups, or anything else. Pruning is best effort: a failed remove is ignored and never stops the import. |

## Acceptance criteria (v1) and traceability
| AC | Statement | Task | Test that fails if it breaks |
| --- | --- | --- | --- |
| AC1 | Add and classify by keyboard only, in ≤ 3 keypresses beyond the title; no default answer | T5 | All 4 Y/N combos land in the right quadrant. Enter/Space/x at the prompt does nothing. Esc cancels. Typing "rn14/" into the title input changes only its value. |
| AC2 | A task's quadrant always matches its flags; moving changes the flags | T1, T6 | quadrantOf for all 4 combos; flagsFor round-trip; pressing `1`–`4` on a focused task |
| AC3 | Reload keeps all tasks, done states, `when`, `who` and order | T10 | Playwright: add task, reload, still present. jsdom: boot twice on a shared stub. |
| AC4 | Corrupt or future-version data is never overwritten; the user is told | T3, T10 | Garbage → backup written, main key untouched until then. Backup write throws → memory mode, main key byte-identical. Version 2 → no writes. Banner renders. |
| AC5 | With storage unavailable, the app works in memory and says so | T3, T10 | Throwing stub → memory mode. Playwright `addInitScript` blocks storage → banner visible. |
| AC6 | Export then import yields identical tasks, and import never replaces without a backup | T11 | Round-trip through `ui/transfer.ts` and the controller (not codec alone). Pre-import backup is written before replace. Backup write throws → import aborted. Cancel → unchanged. Invalid file → rejected, state untouched. |
| AC7 | Delete, Clear done and Drop all can be undone within 5 s, without losing newer work | T7 | Fake timers: undo at 4.9 s restores, 5.1 s is gone. Delete A, add B, undo → A and B both present. Two deletes back to back. Each of the 3 removal kinds. |
| AC8 | Usable at 375 px with no horizontal scroll | T12 | Playwright at 375×812: `scrollWidth ≤ innerWidth`; all 4 quadrants visible by scrolling |
| AC9 | A due Schedule task is flagged on the right local day and moves to Do with one key | T8 | `localToday` at 23:30 and 00:30 under both pinned time zones. isDue for yesterday/today/tomorrow. Only Schedule tasks get flagged. Pressing `1` moves it. |
| AC10 | Delegate rows show who they wait on; Do shows Next | T8 | "Waiting on Sam" renders. Empty who → no label. Next skips a done top item. |
| AC11 | Review re-asks both questions for every open task | T9 | 3 tasks get new flags. Esc mid-review keeps the answered ones. 0 open tasks → "Nothing to review". |
| AC12 | A second tab can't silently overwrite | T10 | Dispatched `StorageEvent` → state reloads. Stale rev at save → no write, banner shown. |
| AC13 | Nothing the app writes can fail to load | T1, T2 | Property test over core ops → serialize → parse |
| AC14 | The app sends nothing to any other origin | T12 | Playwright: every request during a session is same-origin |

Boundary tests named explicitly: title 0 / whitespace-only / 200 / 201 chars after trim; who '' / 80 / 81; version missing / 0 / "1" / 1 / 2; empty board renders four empty quadrants with hints.
